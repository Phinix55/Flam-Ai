# The Audit — tokenizer fertility & serving capacity

An audit of `starter_kit/`: a v0 tokenizer-fertility benchmark (`fertility.py`,
`REPORT_v0.md`) and a serving-capacity report (`bench/`), whose numbers were
about to drive routing and capacity decisions.

**Every number in every deliverable is rendered from a `results/*.json` key.**
Nothing is typed by hand, and the build fails if a numeral appears that cannot
be traced to one.

| | |
|---|---|
| Tests | 154 passed, 1 skipped — `ruff` + `mypy --strict` clean |
| Parity gate | green — reimplementation reproduces the original byte-for-byte |
| Reproducibility | `make reproduce` green from an empty tree, offline |
| Corpus | FLORES-200 `devtest`, 1012 parallel sentences × 7 languages |
| Grid | 4 tokenizers × 7 languages × 5 denominators, paired bootstrap 95% CIs |

## Quickstart

```bash
make setup      # Python 3.11 + exact pinned deps (via uv)
make corpus     # ONLY network stage: FLORES-200 + tokenizers -> .cache/
make check      # ruff + mypy --strict + pytest
make reproduce  # offline, deterministic rebuild of results/ and part*/
```

`make reproduce` regenerates **every** artefact from `starter_kit/` plus the
cached corpus, with no network access. If it is green, every figure in the
submission is reconstructible from source.

## Pipeline

Data flows one direction; no layer is skipped.

```
config ─→ corpus (fetch, validate alignment, normalise)
       ─→ tokenizers (adapter Protocol, one class per backend)
       ─→ metrics (pure counting + pure aggregation)
       ─→ ablation (flag-toggled legacy reimplementation)
       ─→ results/*.json
       ─→ reporting (tables, figures, jinja2 rendering)
       ─→ partA/ partB/ partC/
```

`metrics/` and `bench/` are pure — inputs in, values out, no I/O, no globals.
All I/O lives in `cli.py`, `stages.py`, `corpus/` and `reporting/`.

## How the guarantees work

**The parity gate.** `src/audit/ablation/legacy.py` is a faithful
reimplementation of `starter_kit/fertility.py`. With all flags off it must
reproduce the original two independent ways: byte-exact stdout from running the
real script as a subprocess, **and** bit-exact float equality (`==`, no
tolerance) against the original's own functions loaded read-only. Until
`make parity` passes, no ablation delta is admissible — that is what proves a
delta measures the flaw and not the rewrite.

**No hand-typed numbers.** Templates in `templates/` contain zero numeric
literals, checked before rendering. After rendering, every numeral in the output
must trace to a `results/*.json` key via the `Tracer` that formatted it —
otherwise the build fails and lists the offenders. Numerals that are genuinely
not measurements (a commit SHA, a build timestamp, `B1`, `A100-80GB`) must be
*declared* with a reason, and those declarations are reported.

**Offline by contract.** Analysis stages set `HF_HUB_OFFLINE=1` and read only
from `.cache/`. A missing cache is a hard error naming the repair, never a
silent re-download.

**`starter_kit/` is read-only.** Never edited, moved or reformatted. It is
imported and executed for comparison, never written to.

**Adding a tokenizer or an ablation flag is a one-file change** — one entry in
`config.TOKENIZERS` or one field on `AblationFlags`. `metrics/` never learns a
tokenizer's name.
